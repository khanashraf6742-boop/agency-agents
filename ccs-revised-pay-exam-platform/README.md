# CCS (Revised Pay) Rules, 2016 — study and practice platform

One self-contained HTML file. No external scripts, stylesheets, fonts or data: everything is inlined at build time,
so it opens from a USB stick, an email attachment or a locked-down office machine, and works with no network.

**Open `CCS-Revised-Pay-Rules-2016-Exam-Platform.html`.** That is the whole product.

### The thing this file does that a question bank usually does not

Every question that turns on a figure carries **the slice of the Pay Matrix it turns on**, drawn as the Schedule
prints it: cell numbers across the top, the rupee figure beneath, the column caption (Level, Pay Band, Grade Pay)
above it. The cell the servant starts from is shaded blue and the cell he lands on is shaded gold. Where cells are
skipped to keep the excerpt narrow, the gap is stated rather than closed up silently — an excerpt that pretends to be
contiguous is how a wrong cell number gets learned.

Three shapes are drawn:

* **one column** — the common case, a slice of a single Level;
* **two columns side by side** — for Level 13, where the column as notified on 25.07.2016 sits next to the column
  re-cast by the resolution of 16.05.2017;
* **a mapping table** — where the question is not about a cell but about which Level a Grade Pay enters, or what the
  NPA ceiling is measured against.

## The five facts that carry the paper

1. **2.57, rounded to the rupee, then located.** The product is rounded to the nearest rupee; the figure is then
   placed at the cell equal to it or the next higher cell. It is never placed lower.
2. **The matrix rounds to the nearest ₹100, not upward.** That is why each column regenerates exactly, and why an
   increment is not 3% of what you are drawing.
3. **An increment is a cell, not a percentage.** Rule 9 moves you one vertical cell in the same Level. At the top of a
   Level there is no next cell and the pay stands still.
4. **A promotion increment is taken in the old Level.** One increment where you are, then the equal-or-next-higher
   cell where you are going. Doing it the other way round is the commonest error in the subject.
5. **The option runs from the next increment in the old structure.** It is not a permanent choice and it ends by
   itself; the choice must be made in writing within three months of notification, and once made it is final.

## Where the figures come from

* **Rules** — the CCS (Revised Pay) Rules, 2016 as notified on 25 July 2016 (G.S.R. 721(E)), Rules 1 to 17 with
  their Explanations, Notes and Illustrations. Every rule's statutory text is held in **one** place,
  `build/verbatim.py`, transcribed clause by clause — Rule 7 in full, from (1)(A)(i) through (11), including the four
  conditions in 10(i)(a)–(d) and both provisos to rule 10(2). The plain-language summary is kept separate from the
  text and is labelled *In short*, so the two can never be confused for one another. The audit fails the build if any
  rule's text is not the verbatim text, if rule 7 is missing a sub-rule, or if a question cites a sub-rule that does
  not exist in the statute.
* **Matrix** — Part A of the Schedule, all 543 cells, transcribed and then re-derived. The Level 13 column is
  taken from the resolution of 16 May 2017, which raised the index of rationalisation for that Level from 2.57 to 2.67.
* **Worked illustrations** — the sums printed with rules 7(1)(A), 7(1)(B), 7(2), 9 and 13, each reproduced with its
  rupees and then re-derived from the matrix by the build.

## How it is built, and why you can trust a cell

The matrix is not typed into a table and left there. It is held in `build/paymatrix.py`, regenerated column by column
from each Level's first cell at 3 per cent rounded to the nearest ₹100, and compared with the gazette figures. The
build **fails** on a single disagreement. Then `build/audit.py` re-derives every rupee asserted in an answer, checks
that every cell printed in a question's table is a cell of the Level it claims, and checks that no marked cell is a
figure the question never mentions.

```
pip install -r requirements.txt   # nothing — the build is pure Python 3.8+
cd build
python3 paymatrix.py              # self-check: 19 levels, 543 cells, 0 disagreements
python3 engine.py                 # writes pay.json, matrix.json, rules_out.json
python3 audit.py                  # 53 checks; exits non-zero on any failure
python3 assemble.py               # refuses to write the HTML if the audit fails
node smoke.js                     # 72 behavioural checks against the built file
```

`assemble.py` also writes `Numerical-Set-Worked-Solutions.md`, a printable edition of the numerical set generated
from the same records — so the two cannot drift apart.

## What this is not

A study aid, not a consolidated statute and not legal advice. CAS, MACP and FR 22 are referred to where the rules
lean on them, but the orders themselves are not reproduced. Verify any operative figure against the bare rules before
using it in an office order.
